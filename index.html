Research direction

Intelligent systems for next-generation networks.

I aim to investigate how operating-system mechanisms, programmable network infrastructure, and distributed machine learning can work together to make future networks faster, more autonomous, and more dependable. My industry work gives me a full-stack view, from hardware bring-up and kernel observability to datapath design, time-sensitive networking, and safe automation of network operations.

My IIT Madras research began with a practical constraint: network providers could not share private traffic data. I studied federated forecasting, in which each provider trains locally and shares model updates, and then used the forecasts to investigate when to scale virtual network functions and where to place them. The published experiments used public traces and synthetic data to represent separate providers.

08Reliable Automation

TrustSteer: Evidence-Grounded and Safe Network Troubleshooting POC

Operational problem An automated troubleshooter can turn symptoms into a confident diagnosis without enough evidence. Repeated link flaps, CRC errors, and packet loss may indicate degraded optics, faulty media, a duplex mismatch, congestion, or remote-interface instability; choosing one explanation too early can lead to a change that does not fix the incident and may make it worse.

Architecture I built TrustSteer keeps observation, hypothesis, verified root cause, and remediation separate. An incident-context builder converts live network measurements, logs, configuration, and topology into structured evidence. A hypothesis agent generates possible causes, an evidence planner identifies what each still needs, and typed, read-only diagnostic tools collect the missing network state. A claim-evidence verifier checks whether every conclusion is supported, contradicted, or uncertain before it reaches the action layer, and remediation is gated by risk. Model-generated intent stays separate from deterministic execution controls.

Evaluation framework A repeatable fault-injection framework defines known root causes, relevant evidence, distractors, required diagnostic steps, safe and unsafe remediations, and expected post-action state. Test cases cover incomplete, stale, conflicting, and misleading measurements as well as prompt injection embedded in logs. It measures grounded root-cause accuracy, unsupported assertions, correct abstention, diagnostic tool calls, latency, unsafe actions, and remediation success.

09Network Operations

AgenticOps: Safe Network Change Management

Problem Network alerts need investigation that connects live observations with runbooks and networking knowledge, and any proposed change must be separated from risky, unverified actions.

My work I developed domain-specific troubleshooting skills for an agentic network-operations platform, combining RAG, vector and BM25 search, runbooks, and network tools, along with an orchestration layer for prompts, sub-agents, tool routing, context, and pluggable models.
